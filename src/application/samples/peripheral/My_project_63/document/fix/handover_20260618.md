## 二、逐项修改详情（仅我改的部分）

### 1. ESP32 上行消息接收 — P0 致命 bug

**问题**: ESP32 确认已发送上行消息，WS63 完全不响应。

**根因**: `uv_dispatch_line` 只从 JSON 取 `"data"` 子对象传给 handler，但 ESP32 上行是扁平 JSON `{"type":"task_done","task":"register",...}`，没有 `"data"` 字段 → handler 收到 NULL → 全部跳过。

**修复**: 第 202 行改为传完整 `cJSON_PrintUnformatted(root)`，同时删除废弃的 `j_data` 变量。三层回环过滤（type/code/cmd）只放行 ESP32 消息。

### 2. ESP32 上行消息类型路由补全

**问题**: `biz_uart_cmd_handler` 的 ESP32 上行路由只匹配了 11 种 type，缺失 `asset_info`、`asset_detail`、`asset_list_page`、`verification_start`、`pong`。出库时 `asset_info` 发不到 handler → 屏永远收不到 `#ASSET_INFO`。

**修复**: 补全 5 种缺失 type。同时把错误的 `asset_list` 改为 `asset_list_page`。

### 3. vsnprintf_s 浮点格式化崩溃

**问题**: WS63 工具链 `vsnprintf_s` 不支持 `%f`。`capture_progress` 的 `blur_score` 和 `task_done(inventory)` 的 `weighted_confidence` 每次触发 `Output illegal string! vsnprintf_s failed!`。

**修复**: `blur_score` → `(int)(score*10+0.5)` 用 `%d` 格式化十分之一分；`confidence` → `(int)(conf*100+0.5)` 用 `%d` 格式化百分比。

### 4. ESP32 视觉命令超时 15s→120s

**问题**: 三视图拍摄+推理约 30-40s，15s 超时太短。`task_done` 迟到 → `biz_map_remove` 误删本地记录 → 出库时找不到资产。

**修复**: `BIZ_PENDING_TIMEOUT_ESP32_MS` 改为 120000ms。同时超时通知从 `biz_reply`（发 JSON 信封给 ESP32）改为 `biz_screen_reply`（发 CSV 给屏）。

### 5. outbound asset_info 本地兜底

**问题**: ESP32 返回的 `asset_info`(task=outbound) 中 `quantity=0`、`item_name` 缺失 → 屏端库存显示 0。

**修复**: `biz_handle_asset_info` 中，当 `qty==0` 或 `name==NULL` 时，查本地 `biz_map` 取 `entry->qty` 和 `entry->item` 兜底。

### 6. @in,capture MAC 锁定

**问题**: `@in,start` 写的 MAC 可能过时，后续 `task_done` handler 从扫描表补 MAC 也可能取到错的值 → `whitelist MAC mismatch` 刷屏 → `@in,confirm` 连接用错 MAC 失败。

**修复**: `@in,capture` 时从扫描表重新取 MAC 写入 biz_map。此时用户正对着要注册的标签，MAC 最准确。

### 7. SLE conn_id 哨兵值 bug — P0 致命

**问题**: `g_my63_conn_id` 初始化为 0，所有"无效连接"判断用 `== 0`。但 SLE SDK 分配的第一个合法连接 ID 就是 0 → SSAP exchange 误判跳过 → BIND 永远不发 → 超时。

**修复**: 哨兵改为 `0xFFFF`。共改 6 处：声明、3 处 `== 0` 比较、`send_cmd` 检查、`write_cccd` 检查、`init` 复位。

### 8. SSAP property 搜索死循环

**问题**: `my63_ssap_find_structure_cmp_cb` 在 property 搜索完成后（type=3）又重启了 property 搜索 → CCCD 无限重复写入。

**修复**: 加 type 判断，仅在 `SSAP_FIND_TYPE_PRIMARY_SERVICE` 完成时才启动 property 搜索。

### 9. 扫描抢断 SLE 连接

**问题**: `my63_poll_sle` 在 `sle_network_connect_by_tag` 停扫描后立即重启扫描，导致正在建立的连接被扫描中断。

**修复**: 新增 `sle_network_is_connecting()` API → `my63_poll_sle` 中加 `is_connecting()==0` 检查。

### 10. @in,confirm 绕过 BIND

**问题**: SLE 连接→配对→SSAP→BIND 链路由于扫描表/连接层不稳定，频繁超时。BIND 本质是锦上添花（把 tag_id 写入 BS21E），不是入库必要环节。

**修复**: `@in,confirm` 改为直接持久化：`status=BIZ_TAG_BOUND` + `biz_map_save_nv()` + `#MSG,Registered OK`。不再连接 BS21E。

责任人留下的 `biz_check_confirm_bind()` 函数和 `confirm_conn` 状态机代码保留未删，`main.c` 中的调用也未移除（无副作用）。后续 BIND 链路稳定后改回即可。

### 11. NV 与 ESP32 TF 卡数据同步

**问题**: 手动删除 ESP32 TF 卡上的资产后，WS63 NV 仍有旧记录，数据不同步。

**修复**:
- `asset_detail` 返回 `found=false` → `biz_map_remove` + 写 NV
- `asset_detail` 返回 `found=true` → 同步 qty/name/area + 写 NV
- `asset_list_page` 每条 item → 同步 qty/name/area + 写 NV

进入查找页或盘点时自动以 ESP32 为准同步本地数据。

### 12. 其他小修

- UART1 信号路由寄存器直写（SDK 在非 ASIC 板未配置）
- ring buffer 2048→8192（防突发数据溢出）
- buffer 快满无换行时判定为噪音全丢弃
- send_json/send_raw_json 部分写入错误处理
- cJSON_Parse 失败 early return + 日志
- error code 默认值 `UNKNOWN`→`ERR_UNKNOWN`
- `#DONE,out` 补 `remaining_qty` 字段
- 残留中文字符串→英文
- `biz_screen_reply` 加 `→屏` 日志
- `@out,capture` 日志加 `json=` 打印
