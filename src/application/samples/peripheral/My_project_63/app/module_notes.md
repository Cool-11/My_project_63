# app 模块说明（分析版）

## 模块定位
- app 层只负责系统启动编排、模块初始化顺序、生命周期调度。
- app 层不承载具体业务算法和底层驱动细节。

## 已确认真实入口注册宏
- 入口注册宏为 app_run（在多个官方样例中使用）。

## 启动编排原则
- 按依赖顺序初始化：shared_protocol -> sle_network/uart_vision -> cloud_storage -> business_logic。
- 任一关键模块初始化失败时，必须打印错误并进入可诊断降级路径。
- app 主流程必须输出阶段性心跳日志，防止假死无感知。

## 审查清单
- 初始化返回值统一检查并打印。
- 生命周期回调中禁止阻塞式长耗时调用。
- 出错路径要可恢复或可安全停机。

## 验证思路（串口）
1. 上电确认各模块初始化日志按顺序出现。
2. 人为让某模块初始化失败，确认 app 层捕获并输出降级日志。
3. 观察运行期心跳日志，确认系统没有静默卡死。
